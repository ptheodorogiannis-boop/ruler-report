# v3 Plan G — Output: PDF, cover editor, block icon, per-block AI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real PDF from the server (continuous or one block per page, attachable to automation e-mails), a cover editor, custom-block icon/subtitle/header toggle, and per-block AI analysis with tones.

**Architecture:** `pdf.ts` owns a lazily launched shared Chromium (Playwright) with a two-slot queue and renders the public page through its own URL with the unlock cookie forwarded; the route is token-gated like `/r`. Cover and block options extend `ReportTheme`/`LayoutBlock` and their zod schemas and render in both editor and public page. Per-block AI scopes `extractFacts` to one section and adds a tone instruction; cards carry `blockId` for placement.

**Tech Stack:** as plan D, plus `playwright` as a runtime dependency and the `mcr.microsoft.com/playwright:v1.64.1-noble` Docker base.

**Spec:** `docs/superpowers/specs/2026-10-22-v3-programme-design.md` §4; §3.2 provides `Automation.attachPdf`.

## Global Constraints

- Ledger: `.superpowers/sdd/2026-10-22-v3-g-output/progress.md`; checkpoints instead of commits; demo untouched.
- PDF: A4, `printBackground: true`, margins 12/10/14/10 mm, 60 s timeout, 2 concurrent renders, browser idle close after 5 min, `PDF_ENABLED=auto|off`, 503 when unavailable, 504 on timeout, attachment limit 15 MB.
- Cover: `coverLayout` `banner | header | none` (default banner); `coverText` `#rrggbb`; `showPeriod` default true; `.cover-hero` 21/9 on screen, 32/9 in print.
- Block: `icon` from the 24-icon set in `infographic.tsx` (`ICON_NAMES`); `subtitle` ≤ 120 chars; `hideHeader` hides the title row on public/print only.
- Tones: `general | performance | worst | opportunities | executive`; the general whole-report `analyse()` is unchanged; `AnalysisCard.blockId` decides placement (after its block) and cards without it stay at the top.
- Public report First Load JS stays ~106 kB (PDF menu is a `<details>`; no new client JS on public pages).

## Review Focus

- A password-protected report: `/api/pdf/<token>` without the unlock cookie must return 401 and never render the locked page into a PDF — pinned by Task 1.
- `renderPdf` when Chromium crashes mid-render: the slot is released and the next request still renders — pinned by Task 1 (queue test with a rejecting render).
- `coverLayout: 'none'` with a theme cover image set: no image is drawn anywhere and the editor's Look panel still shows the picker so the user can switch back — pinned by Task 4.
- `hideHeader` on a block with a block colour: the colour still applies to the widgets (`--block`) even though the header is gone — pinned by Task 5.
- `analyseBlock` on a block with no number widgets (only tables/charts): the heuristic text says there is nothing to summarise rather than inventing numbers — pinned by Task 6.
